# Security Architecture and Control Design Standard

A material security architecture must define assets, actors, authority, trust boundaries, data flows, control objectives, least-privilege behavior, secure defaults, denial, revocation, containment, recovery, implementation ownership, creator verification, independent assurance, and residual risk.

Do not approve architecture that relies on hidden interfaces, trusted networks, provider defaults, shared credentials, undefined administrator authority, or controls that cannot be tested.

Return `NO_SECURITY_ARCHITECTURE_CHANGE_REQUIRED` when existing architecture satisfies the approved change.
