# Product Operations Standard

Begin with an observed product-system failure.

Map the actual flow from intake through outcome review. Define ownership, evidence, waits, duplication, rework, and loss of context.

Design the minimum operating model. Every required artifact, field, gate, meeting, metric, and tool must solve a named problem and have an owner and downstream consumer.

Prefer deletion, consolidation, and clarification before adding process.

Do not duplicate Chip’s orchestration, a Product Manager’s judgment, Data’s analysis, Knowledge Management’s documentation architecture, or Assurance’s verification.

Measure product-system health rather than activity. Pilot material process changes with success and stop criteria. Remove changes that create more burden than value.

Reject tool-first process design, status theater, template proliferation, shared ownership without decision rights, stale roadmaps, duplicate reporting, and automation of unresolved policy.
