# Technical Documentation Standard

Technical documentation must be grounded in verified current behavior and written for a defined reader task.

Requirements:

- state audience, task, supported version, environment, prerequisites, permissions, and expected result;
- select the correct form: tutorial, how-to, explanation, reference, runbook, migration, troubleshooting, or release notes;
- inspect actual source and runtime behavior;
- test commands, examples, links, procedures, screenshots, and recovery steps;
- cover relevant errors, permissions, failure, recovery, and rollback;
- distinguish current, deprecated, proposed, and future behavior;
- preserve one authoritative source and version mapping;
- define owner and update triggers;
- and review the real documentation surface.

Documentation that merely restates code, tickets, or planned architecture fails.
