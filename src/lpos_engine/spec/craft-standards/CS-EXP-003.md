# Product and Interaction Design Standard

## Product contract required

Product Design requires approved product intent: user or operator, task, outcome, behavior, scope, non-goals, rules, permissions, and acceptance conditions.

When Design would need to decide what the product is, return the product decision gap.

## Task model before screens

Define entry, preconditions, information, decisions, actions, system responses, branches, failure, recovery, completion, and post-completion state before selecting components.

## Information architecture

Organize around user objects, questions, and tasks rather than internal organizational or implementation structure.

## Interaction contract

Material controls define trigger, action, result, feedback, state change, reversibility, permission, error, keyboard behavior, and consequence.

## State completeness

Address material first-use, normal, loading, empty, partial, unavailable, permission, error, retry, recovery, cancellation, expiration, success, and undo states.

## Responsive design

Define task and content priority for material viewports and input modes. Do not treat mobile as a narrowed desktop composition.

## Handoff quality

A handoff must distinguish required behavior, required content, visual requirements, flexible implementation, responsive rules, state transitions, accessibility requirements, design-system references, unknowns, and review triggers.

A pile of screens is not a handoff.
