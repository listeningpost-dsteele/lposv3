# 4.4.0 — The Code Testing Guild: an executable code-verification gauntlet

This release adds GUILD-040, the Code Testing Guild, as an **additive, executable
code-verification layer**. It does not remove, disable, or replace any existing testing
behavior — the full existing test suite and every prior Standing Operation continue to
run unchanged. What is new is that the operating system can now classify a code change's
risk, enforce a criticality-weighted test gauntlet, and produce independently verifiable
release evidence, all deterministically in code rather than by prompt instruction alone.

## What is new

- **A deterministic criticality classifier** (`lpos_engine.code_testing.classify`) that
  maps change signals to LIGHT, STANDARD, HIGH, or CRITICAL. It is total: unknown or
  absent signals default to STANDARD and it never raises. Destructive operations,
  secrets, financial movement, irreversible migrations, and production infrastructure
  force CRITICAL; auth, permissions, customer data, public APIs, migrations, concurrency,
  and a broad blast radius force at least HIGH.
- **The Code Testing Gauntlet Standard** as data and gates: the cumulative tier →
  required-gate table, plus a release-decision evaluator that REJECTS when a required
  command did not run, when a gate failed or is flaky, or when only a green unit suite is
  offered for STANDARD or above.
- **The Need-to-Change Gate**: a production change requires a reproduction, a demonstrated
  missing behavior, or an objective-constraint proof; absent all three the correct
  successful result is `NO_CHANGE_REQUIRED`.
- **Release evidence packets** with a test-independence rule that mirrors Sentinel: a
  producer cannot audit its own release, so the independent reviewer may not be the
  implementer.
- **A dependency-free testing-manifest loader** that reads repository-native commands and
  never invents a build, test, lint, or type-check command.
- **12 specialists** (SPECIALIST-034 through SPECIALIST-045) in the new Code Testing
  guild, from the Code Test Director to the Release Verification Auditor.
- **Three Standing Operations**: SO-027 Code Test Gauntlet (event-driven, per code
  change), SO-028 Test Suite Health Review (weekly), and SO-029 Critical Path Hardening
  (event-driven, before a HIGH or CRITICAL release).
- **Four Hermes skills**: `code-test-gauntlet`, `code-criticality-classifier`,
  `acceptance-spec-reviewer`, and `test-evidence-auditor`.
- **The `code_testing` engine module** and a small CLI:
  `python -m lpos_engine.code_testing classify|gauntlet`.

## Counts

- Specialists 33 → 45, Standing Operations 26 → 29, benchmarks 55 → 70, schemas
  unchanged at 20.

## Additive and preserving

The Code Testing Guild is additive. Existing testing behavior is preserved: nothing in
the prior release is retired, and the new gauntlet sits alongside — not in place of — the
current tests and Standing Operations. See [Code testing](/includes/code-testing.html).

## Seeing that the code is tested

- **The Test Coverage Map** (`tools/build_test_report.py` → `dist/test-coverage.html`): a
  self-contained page listing every source module, whether it is under test, its measured
  line coverage, and its gauntlet tier. Rows sort by coverage so gaps surface at the top —
  it is honest by design (CLI entry modules that pytest does not import show as low, rather
  than being hidden). Coverage numbers come from running the full suite under coverage.py;
  the page degrades to a static module↔test map when coverage.py is absent, keeping the OS
  itself dependency-free.

## Writing quality

- **`anti-slop-editor` 1.0.1** migrated in from the approved, verified Hermes skill: a
  named-pattern de-AI editing pass that uses minimum-effective edits to preserve Dan, Chip,
  and LPOS voice, enforces deterministic lint behavior, and explicitly refuses to guess
  whether text was AI-authored. CS-001, zero em dashes, and independent review remain
  authoritative. Preserved alongside it (unchanged): `quality-router` 2.2.0 prose routing,
  `lpos-core` 3.1.0 writing rules, and the voice/editor overlays — migrated explicitly
  rather than by editing a signed release in place.
