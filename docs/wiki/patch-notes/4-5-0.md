# 4.5.0: writing and design quality gates

LPOS now packages the `design-anti-slop-reviewer` beside the existing Anti-Slop Editor.
The change applies the same rule to prose and visual work: name observable failures,
make the minimum coherent correction, and prove the exact final artifact before it can
be delivered or published.

## What changed

- Customer-facing prose routes through the Anti-Slop Editor, CS-001, deterministic lint,
  and independent review.
- Customer-facing visual work routes through CS-002 and the Design Anti-Slop Reviewer.
- Visual releases require desktop and mobile evidence, accessibility and interaction
  checks, zero deterministic blockers, and independent review.
- Fabricated ratings, reviews, testimonials, guarantees, metrics, and fallback identities
  are truth failures and release blockers.
- Paid products claiming LPOS quality must carry the required skills through the catalog,
  immutable job version, signed run envelope, validator, reviewer record, and final gate.
- SO-022 executes the quality gate before it records any publication action. Missing proof,
  remaining blockers, fabricated claims, or review bound to another artifact stop the workflow.
- Release verification excludes Git metadata and is tested against a clean export of the
  exact committed candidate.

## What did not change

The Code Testing Guild, specialists, Standing Operations, benchmark corpus, schemas,
record-only external-action default, and existing v4.4 operating behavior are preserved.
