# LPOS 4.8.3 — Model Routing Enforcement

Date: 2026-08-13

## Problem

Guild model routing lived in skills and docs. `lpos managed-run` still launched ambient default Hermes (usually the interactive main model). Operators and agents burned GLM/OpenAI/Kimi credits while believing guilds ran on mapped lanes.

## Fix

Executable routing table + preflight gate:

- `src/lpos_engine/model_routing.py`
- `src/lpos_engine/config/model_routing.json` (v1.4 guild lanes)
- `managed-run` preflight binds or rejects `--hermes-command`
- CLI: `lpos route list|resolve|check|install-wrappers`
- Override config: `LPOS_MODEL_ROUTING_CONFIG`, `~/.hermes/lpos-model-routing.json`
- Emergency disable: `LPOS_MODEL_ROUTING_ENFORCE=0`
- Break-glass: `--authorize-model-override`

## Operator usage

```bash
lpos route list
lpos route resolve --guild GUILD-SOFTWARE-ENGINEERING
lpos route check --guild GUILD-SOFTWARE-ENGINEERING --hermes-command hermes-gpt56
lpos route install-wrappers --target-dir ~/.hermes/bin

lpos managed-run \
  --workdir /path/to/repo \
  --specialist SPECIALIST-... \
  --reviewer SPECIALIST-... \
  --artifact path/in/repo \
  --instruction "..." \
  --hermes-command hermes-gpt56
```

Bare `--hermes-command hermes` auto-binds to the guild wrapper when the wrapper exists on PATH or under `~/.hermes/bin`.

## Receipt compatibility

`lpos managed-run` now accepts `$schema` as an alias for `schema` when the value is the LPOS receipt type (`lpos.managed-review.v1` or `lpos.managed-contribution.v1`). A JSON Schema URL in `$schema` does not override a valid `schema` field. Object-shaped `corrections` arrays are normalized to issue text so a second review cannot crash the run.
